### Текущие проблемы:
* Взаимодействие между сервисами происходит синхронно, после получения данных. Соответственно, даже если данные из внешних систем успешно получены, то из-за внутренних проблем (например, сетевой ошибки) они могут быть потеряны
* Т.к. запрос синхронный, то ответ ждёт самого медленного запроса, и, возможно, при сбое в одном из внешних API не возвращает вообще никакие данные

### Риски, связанные с ростом нагрузки:
* Увеличение рисков проблем при получении данных с ростом нагрузки и (возможно) количества поставщиков данных
* Повышение сетевой нагрузки (количества трафика) от агрегатора к приложению
* Доставка актуальных данных не гарантируется
Отсутствие гарантии передачи данных во время выполнения синхронных запросов (раз в 15 мин и раз в 24 часа).

### Transactional Outbox
Предлагаю использовать паттерн для сохранения результатов от внешних сервисов перед отправкой в брокер сообщений (для избежания перезапросов внешних API и гарантии доставки)
